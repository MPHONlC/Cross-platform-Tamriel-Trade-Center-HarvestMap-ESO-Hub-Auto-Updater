### Version 2026.10.23.09.34 <sub>*(10/23/2026)*</sub>

#### APH-OnManager (All Platforms)
* Added APH-OnManager data updates. When APH-OnManager is installed and you turn them on,
  the updater downloads its add-on data tables from the APH-OnManager GitHub repository an
  hour after each of the five daily data refreshes (01:06, 05:54, 10:42, 15:30 and 20:18
  UTC) and merges them into your copy. Entries only you have are kept, and an older version
  from GitHub never replaces a newer one.
* Added an APH-OnManager Data question to setup. It only shows when APH-OnManager is in
  your AddOns folder, and Yes is the default. If you install APH-OnManager later, the next
  run in a terminal asks once and waits a minute for an answer; hidden runs leave its data
  alone until you answer. Run the updater with --setup to change the answer.
* Changed the check to wait for the next cycle while a data refresh is still running. If a
  table can't be downloaded, nothing is changed and the updater tries again next cycle.
* Changed a linked APH-OnManager folder to be left alone, like the add-on updates already
  do.

#### Self-Update (All Platforms)
* Added this project's GitHub releases as a second source for updating the updater itself.
  It now checks both ESOUI and the GitHub releases every 6 hours and installs whichever
  version is newer. GitHub tags are read as Version-<CalVer>, and only the
  Tamriel_Trade_Center_Auto-Updater.zip asset is used. These are read-only requests.

#### TTC (All Platforms)
* Changed the TTC price table check to TTC's own method: the updater asks TTC for the
  price table version at most every 45 minutes and only downloads when TTC's number is
  higher than the one in your PriceTable file. TTC updates that file about once a day.
* Fixed the price table check waiting after TTC was installed or reinstalled. The next
  cycle now checks right away.
* Renamed "Checking TTC APIs..." to "Checking TTC Server...".
* Changed the version lines so an out-of-date Local version shows in red and the Server
  version in green.

#### ESO-Hub (All Platforms)
* Updated ESO-Hub to the v2 API the current ESO-Hub Client uses, sending the same client
  headers. The old v1 API stays as a fallback for the add-on list, downloads, uploads and
  login, so the updater uses whichever one answers.
* Added a SHA-256 check on ESO-Hub add-on downloads. A download that doesn't match
  ESO-Hub's checksum is not installed.
* Changed ESO-Hub add-on updates to read the IntVersion from the installed add-on, like
  the ESO-Hub Client does. A copy newer than ESO-Hub's is never replaced with an older one.
* Changed uploads to ESO-Hub's v2 format, one zip with the add-on's save files. The old
  one-file upload is the fallback.
* Fixed "Could not fetch ESO-Hub data." giving no reason. When ESO-Hub's server answers
  with a Cloudflare check instead of data, the updater now says so, skips ESO-Hub for that
  cycle, writes it to the log and keeps updating TTC and HarvestMap. Other errors name the
  HTTP status.
* Changed the ESO-Hub login in setup so your username and password no longer appear on
  curl's command line.
* Removed the Manually enter API Token option from the ESO-Hub question in setup. Log in
  through your browser or with your username and password, or skip to upload anonymously.
* Added Log in through your browser as the first ESO-Hub choice in setup. It works like
  the ESO-Hub Client: the updater opens ESO-Hub's login page with a one-time code, you log
  in and link the device there, and the updater receives the Login Token. Your password is
  never typed into the updater. It waits up to 5 minutes, and Enter stops waiting. While
  ESO-Hub's data server answers with a Cloudflare check, the updater also asks for
  cf_clearance, since it picks up the Login Token from that server.
* Added a way past ESO-Hub's Cloudflare check. When ESO-Hub answers with the check and the
  updater runs in a terminal, it opens eso-hub.com in your browser, shows where to copy the
  cf_clearance cookie, and tries again as soon as you paste it. The cookie and your
  browser's User-Agent are saved and only sent to eso-hub.com. When ESO-Hub stops accepting
  them, the updater asks again; hidden runs say how to do it instead.
* Added reading your browser's User-Agent by itself during the browser check, so only
  cf_clearance has to be copied. The browser first opens a one-time page on your own PC
  (127.0.0.1) that passes it straight on to ESO-Hub. When that page can't be opened (Linux
  and macOS need python3, perl or nc; Windows needs a local TcpListener) or the browser
  doesn't reach it within 30 seconds, the updater names the reason and asks you to paste the
  User-Agent as before.
* Changed the Cloudflare prompt to a single "ESO-Hub Human Verification Required:" header,
  and before you paste it added a short note on what cf_clearance is, that it is a human
  check, and that it stays on this PC and is sent only to eso-hub.com.
* Changed the page the check opens from the ESO-Hub home page to your ESO-Hub profile
  page, so you land where you log in and verify. The link follows your system language
  (English for now, until more are confirmed).
* Changed the Server and Local version lines so an out-of-date Local version shows in red
  and the Server version in green.
* Changed the updater to re-read the saved cf_clearance from its config at the start of
  each ESO-Hub cycle, so a long-running or autostart copy picks up a refreshed cf_clearance
  without a restart (edit lttc_updater.conf, or re-run setup). A failed ESO-Hub Cloudflare
  check never stops the loop: it skips ESO-Hub for that cycle, logs it, and goes on to
  HarvestMap and the next run; an unanswered prompt times out after 5 minutes and skips the
  same way.
* Clarified the ESO-Hub browser check: it asks again only when a real request to ESO-Hub
  fails (ESO-Hub's Cloudflare check expires in about half an hour on their side, which is
  separate from how long your browser keeps the cookie), and it stops for the session if you
  skip it. Hidden and Steam game-mode runs never prompt; they skip ESO-Hub until the cookie
  is refreshed.
* Added an optional setting to read cf_clearance from your browser by itself (Linux and
  macOS, including the Steam Deck; off by default, setup asks once). When ESO-Hub returns
  its Cloudflare check and the setting is on, the updater reads only ESO-Hub's own
  cf_clearance cookie from Brave, Chrome, Edge, Vivaldi, Chromium or Firefox, pairs it with
  the User-Agent it already saved, and retries. It copies the cookie database read only,
  never touches other cookies or sites, keeps everything on this PC, and falls back to the
  copy-paste prompt whenever it can't. A hidden or autostart copy can refresh this way with
  no prompt. Windows still uses copy-paste.

#### Add-Ons (All Platforms)
* Changed the add-on version change display to a pacman-style diff: the old version is
  shown with only the digits that changed in red, a green arrow, then the new version with
  only the changed digits in green. TTC and ESO-Hub also show an out-of-date version in red
  and the current one in green.
* Changed every progress spinner to an animated pacman eating a row of dots (parsing,
  merging, uploading, downloading). On Windows it animates through a background runspace,
  falling back to a static frame if that can't start.

#### Security (All Platforms)
* Added scrambling for the saved secrets. Your ESO-Hub token, cf_clearance, browser
  User-Agent, TTC client ID and account name are no longer stored as plain text in
  lttc_updater.conf. On Linux and macOS they are scrambled with a key tied to this machine
  (openssl); on Windows they are protected with Windows DPAPI, tied to your Windows account.
  The file stays readable only by your user on Linux and macOS.
* Changed nothing you have to do: an existing config is re-scrambled the next time it is
  saved, and a copy moved to another machine or user simply can't be read, so the updater
  asks you to log in again there. This stops casual reading and accidental sharing; it is
  not unbreakable, since the script is open source.

#### Database (All Platforms)
* Added a summary line after the history prune: how many entries remain, the file size,
  the age of the oldest and newest entry, and how many entries are near the 30-day cutoff.
  History is pruned every cycle, so there is no scheduled prune date.
* Added a trade-history line after a merge (from your own sales or the shared template):
  how many listings are new, how many were updated, and the file size before and after.
  Merges only add or update, they never delete; deletion happens only in the 30-day prune.
* Fixed the ESO-Hub login in setup failing without a reason. It now says whether
  Cloudflare stopped it, ESO-Hub refused the username and password (with ESO-Hub's own
  message) or there was no connection. When Cloudflare stopped it, setup asks for the
  browser check and logs in again.
* Changed lttc_updater.conf on Linux and macOS to be readable only by your user, since it
  holds your ESO-Hub token and browser check.

### Version 2026.10.04.19.22 <sub>*(10/04/2026)*</sub>

#### New Features (All Platforms)
* Added optional updates for the other add-ons and libraries in your AddOns folder: setup
  now asks whether to keep them up to date. When it's on, the updater compares them with
  ESOUI every 6 hours, installs newer versions and keeps the previous copy in
  Backups<kbd>/AddOns</kbd> for 30 days. Linked folders, HarvestMapData and the ESO-Hub
  add-ons (which already update from ESO-Hub) are left alone.
* Updated the last 30 days of trade history from the Auto-Updater Database Template. When
  a newer template exist, its TTC and ESO-Hub listings and sales are merged into your own
  history without counting anything twice.
* Changed the database template to CalVer like the updater. Copies still on 0.0.x update to it.
* Updated uploading to Tamriel Trade Centre.
* Fixed some item colors in the listing log.

#### Layout
* Added a separate macOS script, macOS_Tamriel_Trade_Center.sh. The Linux script is now
  Linux-only, so a bug on one platform can be fixed without touching the other.
* Changed versioning.

#### Windows Fixes
* Fixed the known bug where pressing "b" to browse the database while the updater was
  looping hid the output and switched the updater from loop mode to run-once.
* Fixed ESO-Hub sales picking up item names left over from the TTC step, which could show
  the wrong name or none at all.
* Fixed history records being appended as duplicates on every scan. Windows now merges
  them into one line with a scan counter, same as Linux.
* Fixed the 30-day history prune deleting the history version header and failing on short
  or damaged rows.
* Fixed the database browser reloading the whole config file when you open it. It only
  reads your saved @Username now.

#### macOS Fixes
* Fixed ESO-Hub on macOS only ever checking and updating the first of EsoTradingHub,
  EsoHubScanner and <kbd>LibEsoHubPrices</kbd>.
* Fixed the database browser's "@Username only" filter stopping with an error on macOS.
* Fixed rerunning setup on macOS adding a second launch command to Steam's Launch Options,
  and the script path being quoted in a way that broke Steam's config file.
* Changed the macOS desktop shortcut to a .command file on your Desktop that opens in
  Terminal.
* Changed macOS to replace an older Linux_Tamriel_Trade_Center.sh in
  Unix_Tamriel_Trade_Center with the macOS script, so Steam launch options that point at the
  old name keep working.

#### Linux, macOS & Steam Deck Fixes
* Fixed hidden runs that Steam didn't start closing after the first update whenever ESO
  wasn't open, so login autostart stopped almost right away. They now keep their hourly
  cycle, like on Windows.
* Fixed the updater taking up to 5 seconds to close after being told to stop while waiting
  in the background.
* Removed the need for rsync, and for perl outside the optional Steam launch options step.
  The script now checks for the tools it does need and names any that are missing.
* Fixed setup changing the launch options of each Steam account twice when
  ~/.steam<kbd>/steam</kbd> and ~/.local<kbd>/share</kbd><kbd>/Steam</kbd> are the same
  folder.

#### Fixes (All Platforms)
* Added a log line naming the ESOUI file when an update of one of your add-ons fails.
* Fixed TTC price tables never downloading after the updater installed TamrielTradeCentre
  for you (the add-on's version number was saved as the price table version).
* Fixed issue where "Both (NA & EU)" uploading your TTC data to the EU server only. It now
  uploads to both.
* Fixed database updates from ESOUI keeping duplicate trader location rows.
* Fixed TTC entries borrowing the price, amount, sale time or name of the entry before
  them when a field was missing.
* Fixed trader map links with a broken ping parameter, so the ESO-Hub map opens on the
  exact trader spot again.
* Fixed rows without a guild showing the trader location of the row before them.
* Fixed the HarvestMap snapshot being saved even when the download failed, which skipped
  the retry.
* Fixed the database auto-repair running before the SavedVariables folder was known.
* Fixed the price calculator breaking on item names with brackets or other special
  characters.
* Fixed the price calculator listing results in a different order every run. Results are
  sorted by item name now.
* Fixed the item database file order depending on the system language settings.

#### Windows Additions
* Added the Linux download safety net.
* Added <kbd>LibEsoHubPrices</kbd> to the missing add-on installer.
* Added the --setup, --addon-dir and --desktop options. The desktop shortcut now passes
  --desktop so the log shows how the updater was started.
* Added the log line that records the launch method (Steam, desktop shortcut, background
  task or double-click).
* Added the cleanup for leftover title tags in older database files.
* Added the Linux progress spinners with completion times for parsing, uploads, downloads,
  pruning and cleanup.
* Added the HarvestMap server and local status lines.
* Added version detection on first run for ESO-Hub add-ons you already have, so they don't
  all show as out of date.
* Added skipping the EsoHubScanner upload when the file has no scanned items.
* Added the persistent <kbd>/Cache</kbd> folder to the database browser, so Top 10 and
  price results load instantly until new data arrives.
* Added UESP Wiki links for furniture plans, crafting motifs and style pages in the
  database browser.
* Improved Top 10 and suggested prices to use the Linux math: scan-weighted prices,
  outliers trimmed, and at least 5 data points.
* Improved TTC parsing speed. A 535 KB TamrielTradeCentre.lua went from about 2.2 to 0.9
  seconds in testing.

#### Linux, macOS & Steam Deck Additions
* Added "View / Search Database" to the database browser: search by name, guild, player or
  trader town, filter by source, your @Username and time, sort by date, price or name, 50
  results per page.
* Added "View Previous Extraction History", which lists what the last scan found with the
  same search and sorting.
* Improved Top 10 and price calculator sorting speed, about 7 times faster on large
  histories.

#### Parity
* Changed both scripts to share the same menus, messages, database format and results.
  Given the same SavedVariables, Linux, macOS and Windows should now write byte-identical
  history and database files.
